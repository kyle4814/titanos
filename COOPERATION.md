# Cooperation

For anyone arriving with a problem, a resource, or a question about
partnership, investment, acquisition, or licensing — this page states
what's actually possible right now, plainly. It reuses the rest of this
repository's canonical documents rather than restating them; where it
links instead of repeating, that's the source of truth, not this file.

**Nothing on this page is an offer, a solicitation, or an agreement.**
No document in this repository creates a binding commercial or legal
obligation by existing, being read, or being filled in. Filing an issue
creates no entitlement on either side. A human — not an automated
system — reviews every engagement; nothing here executes, spends,
signs, or binds anything.

## What this system can actually help with

See `README.md`'s "What's here" table for the verified subsystems
(schema validation, epistemic classification with forbidden-transition
enforcement, threat taxonomy that structurally blocks narrative from
becoming technical evidence, legacy-system bottleneck mapping with a
human-review gate, and the rest). See `PARETO_FRONTIER.md` for what's
proposed but not yet built, and `HUMAN_DECISIONS.md` for open judgment
calls — a problem that maps onto one of those is a real, specific thing
to bring, not a guess. `CAPABILITY_MANIFEST.json` gives the same
per-subsystem facts in a structured, machine-parseable form, if that's
more useful than prose.

## What kind of problem you can bring

Anything that maps to a real gap: a claim in this repository you can't
reproduce, a bottleneck-mapping or epistemic-classification problem in
your own domain that looks like what `rpa/` or `kpm/` already do, a
security/threat-taxonomy question `taal/` might address, or a genuine
capability gap this repository doesn't yet cover. The **"Bring a
bottleneck"** issue template
(`.github/ISSUE_TEMPLATE/bring_a_bottleneck.yml`) is the structured way
in — problem, evidence, resource offered, all with an explicit
no-entitlement acknowledgment.

## What resource or value you can offer

Compute, engineering time, domain expertise, a real-world use case,
independent review, data, distribution, infrastructure, or access —
named as *possible* contribution classes, not a request. Naming a
resource creates no obligation on either side. Money is one possible
resource among these, not a requirement or a default expectation.

## Cooperation structures — named as principles, not live terms

These are the *shapes* a real cooperation could take, if one is ever
actually negotiated. None of them exist yet as a live agreement:

- **Bilateral, explicit-weight cooperation.** Two parties, contributions
  and weights stated plainly, not assumed equal by default.
- **Resource-for-value.** A contribution (compute, expertise, access,
  ...) exchanged against a measurable outcome — baseline, measurement
  method, and success condition all stated explicitly before anything
  starts, never inferred afterward.
- **Deferred / conditional pathway.** A system that's genuinely
  resource-constrained now is not automatically disqualified from
  cooperation. Any such arrangement is a bounded, negotiated,
  explicit-terms proposal — never an unlimited, open-ended, or invented
  obligation ("help now, owe forever" is exactly what this doctrine
  forbids).

**No percentage, valuation, revenue share, equity, or payout figure is
stated anywhere in this repository as a standing term.** Any such
number would only ever be one specific negotiated outcome of one
specific agreement — never a general claim this page or any other
document here makes.

## Investment, acquisition, and licensing enquiries

There is no due-diligence package, data room, or standing offer.
The path in is the same as any other engagement: the issue template
above, or a direct pull request if it's code. What happens next is a
human conversation — nothing here auto-qualifies, auto-accepts, or
auto-rejects an enquiry.

## What's fixed, negotiable, or requires legal review

**Fixed:** the MIT license on the code (`LICENSE`) — that's the one
standing, unconditional term in this repository. **Everything
commercial is negotiation-only and legal-review-required before any
agreement exists** — no template on this page, in this repository, or
implied by any doctrine file here is a contract, a term sheet, or
legally binding, and none should be treated as such by either side
until independent legal review has actually happened. No jurisdiction
is assumed or claimed.

## Where human authority remains

Every consequential action in this codebase is gated the same way
regardless of who's asking: `foundation/publication_gate.py`,
`foundation/communication_gate.py`, and `foundation/hells_gate.py` all
default closed and require an explicit, named human authorization to
open — see `HUMAN_DECISIONS.md` for the standing list of what's still
open. No automated system in this repository can spend money, sign
anything, transfer value, or create a legal or financial commitment —
that authority is not delegated to code anywhere here, and any future
automation (a bot, a smart contract, or otherwise) would need its own
separate, explicit engineering, security, and legal authorization
before it could touch any of this — none currently has one.
