## THE CORE CLAIM

`PARETO_FRONTIER.md` is not a backlog — it's the navigation surface
between verified current capability (code + tests) and the smallest
credible next capability. Each active entry must answer the **Frontier
Gate**: CURRENT (what exists) / GAP (what's missing) / LEVER (why it
matters) / FIRST STEP (smallest proof) / PROOF (how it's verified) /
UNLOCK (what becomes reachable) / REUSE (what it builds on). An entry
that can't answer these stays in `INTUITION.md` — a new low-commitment
discovery surface for observations, patterns, and questions that are
promising but not yet evidence-backed enough to become committed work.
Frontier maintenance is part of production: after every cycle, archive
what's `BUILT` out of the active scan path (one-line summary + commit
hash, not deleted), reformat what changed, and select the next move.
